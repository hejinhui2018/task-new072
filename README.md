# 直播控制室 · 前端性能巡检台

一个**纯浏览器本地模拟**的帧级性能巡检工作台：把一次复杂操作（内置「切换直播画面」场景）拆成若干主线程任务，
按 60fps 的 **16ms 帧预算**逐帧回放，直观回答“这波操作为什么掉帧”。

不依赖任何真实设备、后端或外部服务；调度器是一个**无随机数、无系统时钟的纯函数**，同一份参数永远产生同一条时间线（确定性重放）。

技术栈：React 18 + TypeScript + Vite，测试用 Vitest。

## 运行方式

```bash
# 1. 安装依赖（Node 18+）
npm install

# 2. 本地开发（默认 http://localhost:5173）
npm run dev

# 3. 跑测试（帧预算 / 优先级 / 抢占取消 / 长任务 / 确定性重放，共 26 个用例）
npm test
# 或 watch 模式：npm run test:watch

# 4. 类型检查 + 生产构建（输出 dist/）
npm run build

# 5. 预览生产构建
npm run preview
```

`npm test` 通过（26 passed）且 `npm run build` 成功即表示环境就绪。

## 界面能看到什么

- **指标瓦片**：掉帧数及**掉帧帧号**、全部任务完成时间（ms / 帧数）、长任务数、推迟/让出次数、取消节省/白跑时间。
  每个指标都会与未调参的内置默认场景（基线）对比，标出增减。
- **帧时间线**（可横向滚动、缩放）：
  - 每格是一帧的 vsync 窗口，标有帧号与时间区间；
  - `▲` 任务在帧首入队；`●` 黄色=取消成功、红边=取消被拒；
  - 彩色切片是主线程占用（颜色=任务类型）；**红色斜纹切片 = 长任务**（越过 16ms 截止线）；
  - 虚线右边框表示可取消任务在帧边界主动让出；`⏸` 表示该任务本帧被推迟；
  - 掉帧的帧格标红，被长任务整帧阻塞的帧带斜纹底；悬停任意元素有解释性 tooltip。
- **传输控制**：▶ 播放 / ⏸ 暂停 / ⏭ 单步 / ↺ 重放，三档播放速度；也可以直接点某一帧跳到该帧。
- **帧检视器**：点击帧后逐帧列出到达事件、取消裁决、主线程切片区间、推迟明细。
- **任务结算表**：每个任务的最终状态、实跑时间、长任务标记、让出/推迟次数、取消白跑与节省。
- **巡检结论**：把模拟数据翻译成自然语言（哪个长任务波及了哪些帧、推迟原因、取消裁决、汇总结论）。
- **任务编辑区**：可改每个任务的**优先级、预计耗时、到达帧、可取消性**，增删任务，并给任意任务**添加取消请求（指定帧）**。
  改动后整条时间线与所有指标立即确定性重算；「↺ 恢复内置场景」一键还原。

### 内置场景：切换直播画面

| 任务 | 默认优先级 | 默认耗时 | 可取消 | 含义 |
|---|---|---|---|---|
| 解码新画面分片 | 关键 | 22ms | 否 | 模拟不可中断的同步解码回调，默认即为长任务 |
| 布局重排 | 高 | 9ms | 是 | 帧边界可协作让出 |
| 写切换操作日志 | 普通 | 4ms | 是 | 帧边界可协作让出 |
| 预加载下一机位 | 低 | 30ms | 是 | 用户可能立刻再切走，典型的可取消任务 |

默认参数下第 0 帧解码原子执行 22ms → 第 0、1 帧连续掉帧，预加载被反复推迟。建议的巡检动作：

1. 给「预加载下一机位」在第 1 帧加取消请求 → 观察完成时间缩短、掉帧归因不变（瓶颈是解码），并看到“白跑/节省”时间；
2. 把解码耗时降到 12ms 或把优先级调整 → 观察掉帧数归零；
3. 把某个可取消任务改成不可取消并拉长到 >16ms → 观察它如何变成长任务并阻塞后续帧。

## 调度模型（`src/engine/scheduler.ts`）

- 时间以 **0.1ms（tick）为最小单位做整数运算**，杜绝浮点误差；第 `i` 帧窗口为 `[i×16, i×16+16) ms`。
- 每个窗口只处理**帧首 vsync 时刻已入队**的任务；窗口内到达的任务下一帧才可见。
- 选取顺序：**优先级（关键 > 高 > 普通 > 低）→ 到达帧 → id**，与输入数组顺序无关。
- 任务剩余工作量 ≤ 当前帧剩余预算：直接跑完。
- 任务比**一整帧还大**且可取消：用完当前帧剩余时间后在帧边界**协作让出（抢占切片）**，下帧继续，不算长任务。
- 任务短于一整帧但当前剩余预算不够：**整任务推迟**，调度器继续尝试后面更短的任务“填洞”。
- **不可取消**任务一旦开始就原子执行完；越过 vsync 截止线即**长任务**，溢出时间会让后续帧部分阻塞或整帧阻塞（掉帧）。
- 取消请求在帧首裁决：未开始→`已取消`；已执行一部分→`部分取消`（白跑已执行时间，剩余时间不再占用主线程）；
  已结束 / 不可取消 / 尚未入队或不存在 → 对应**拒绝**结果。
- 掉帧判定：帧首主线程仍忙（上帧溢出）**或**帧末主线程越过窗口截止线。

## 测试覆盖

`src/engine/scheduler.test.ts`：

- **帧预算**：恰好 16ms 不掉帧、超预算切片、空闲帧不入时间线、自定义预算、非法输入；
- **优先级**：同帧按优先级选取、低优先级被推迟并记录帧号、已开始任务不被同帧晚到任务打断；
- **抢占**：可取消大任务帧边界切片且不掉帧、被抢占任务下帧仍先于低优先级任务；
- **取消**：未开始取消、部分执行后取消（白跑/节省）、不可取消被拒、完成后被拒、未入队/不存在被拒；
- **长任务**：越线标记、波及帧归因（部分阻塞/整帧阻塞）、长任务期间到达任务延后执行、改可取消后掉帧消失；
- **确定性重放**：同输入两次结果全等、打乱输入数组顺序结果不变；
- **内置场景**：默认有长任务/掉帧、取消预加载后完成时间缩短且节省被统计、降低解码耗时后掉帧归零。
